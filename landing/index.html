The Problem

Multi-agent debugging is
still stuck in the dark ages

When a 4-agent pipeline fails at step 3, you have no idea which agent caused it, what state it was in, or how to fix it without re-running the entire expensive workflow from scratch.

🌑

Flat logs tell you nothing

Standard logging doesn't capture parent-child agent relationships. You see a wall of text, not a tree of causation.

💸

Every fix costs a full re-run

Fixing a prompt in agent 3 means re-running agents 1 and 2 again — wasting tokens and time on work that was already correct.

🔄

Loop detection is manual

Agent A calls agent B calls agent A. Your pipeline spins until you kill it. No tool catches this automatically.

🤷

No shared observability standard

Every agent framework emits different telemetry. There's no OpenTelemetry-compatible tool that understands multi-agent state.

The Solution

Three things no other
observability tool does

01
🌳

Hierarchical Span Trees

Every agent action is recorded as an OpenTelemetry span with parent-child relationships. Visualise the full execution tree as an interactive graph — click any node to inspect its input, output, tokens, and cost.

02
⏪

Time-Travel Replay

Fork execution from any past step. Edit a prompt or tool output, hit replay, and only the downstream agents re-run. The original trace is preserved. A new forked trace appears so you can diff the two side by side.

03
🧑‍⚖️

LLM-as-a-Judge Evals

One click runs an LLM judge (Groq LLaMA 3.3 70B) over every agent output. Get relevance, reasoning, and quality scores per span — catch regressions automatically without reading logs.

How It Works

Instrument once.
Debug forever.

1

Instrument your agents

Send OpenTelemetry spans to POST /ingest using your API key. Works with LangGraph, CrewAI, AutoGen, or any custom agent framework.

2

Watch the tree form

Every span is stored with its parent ID, input/output payloads, token usage, and cost. SwarmTrace builds the hierarchical tree automatically.

3

Click any node to inspect

The React frontend renders an interactive graph. Click any span to see its full state, run the LLM judge, or edit its output.

4

Fork & replay from that step

Hit "Fork & Replay". The backend loads the state snapshot at that step, injects your edits, and resumes the swarm — only the downstream agents re-run.

Quickstart

Self-host in 5 minutes

Docker Compose handles everything. You need Docker, a free Neon Postgres account, and a free Groq API key.

# 1. Clone the repo
git clone https://github.com/codewithleo1/SwarmTrace
cd SwarmTrace

# 2. Set your env vars
cp backend/.env.example backend/.env
# Edit backend/.env — add GROQ_API_KEY and DATABASE_URL

# 3. Start everything
docker compose up

# Frontend: http://localhost:5173
# Backend: http://localhost:8000
# Docs: http://localhost:8000/docs
# Backend (Python 3.12 + uv)
cd backend
uv sync
uv run uvicorn main:app --reload

# Frontend (Node 20+)
cd frontend
npm install
npm run dev

# Run the demo swarm
uv run python -c "from agents.orchestrator import run_swarm; run_swarm('AI agents')"
